# 古法蓝晒 · 漏光补晒准入台

漏光底片的补晒准入、修边复核与入盒工作台。业务拆成三个文件：

- `判定.js`：准入判定、更正重算、修边换人复核、入盒预检、队列与统计规则（纯逻辑，不碰文件/网络）
- `存档.js`：JSON 存档读写、初始数据、旧版结论留档
- `页面.js`：工作台 HTML 与前端交互（列表、曝光队列、统计同源刷新）
- `server.js`：HTTP 路由薄层，组合以上三个业务文件

## 业务规则

1. 同一底片只允许一张未结束检测单；重复登记直接沿用首次那张，不新建。
2. 登记字段：漏光占比、遮挡批次、补晒秒数、检查人。
3. 漏光占比超过 **15%**、遮挡批次已停用、或补晒不足 **90 秒**：结论为「待修边」，不进入补晒队列、不占曝光位；三条全过才进入「补晒排队」。
4. 修边必须换人复核两次（复核人不能与检查人或彼此相同），两次漏光均不高于 **5%** 才可入盒。
5. 更正漏光占比或遮挡批次会让结论失效：旧版结论快照留档、版本号 +1 后按新数据重算；状态随之迁移，旧修边复核作废。
6. 列表、曝光队列、刷新后的统计全部由同一份存档派生，数字始终一致。

## 运行

```bash
npm start
```

访问 `http://localhost:3040`。数据保存在 `data/light-leak-resun-desk.json`（首次启动自动生成示例数据）。
